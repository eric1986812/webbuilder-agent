海外网站开发 Agent — 完整工作流 v1.0

定位：能主动完成 市场调研 → 选项目 → PRD → 技术文档 → 编码 → 测试 → 部署 整链路的海外网站开发 Agent。
目标用户：OPC 创业者 / 超级个体 / 想做出海 SaaS / 工具站的人。
设计原则：MSP > MVP，每个 Phase 都有明确 Gate，进可攻退可守。

0. Agent 能力清单（一次说清能干什么）

能力 是否支持 备注
海外市场调研（行业 / 竞品 / 政策） ✅ 输出物：行业分析.md
项目方向筛选（决策矩阵） ✅ 输出物：候选项目.md

每个 Phase 结束时都有"继续 / 调整 / 暂停"的决策 Gate，避免让老板烧完一轮才发现方向错。

Phase 1：市场调研（Market Research，3-5 天）

1.1 目标地区与赛道初筛

  • 输入：老板指定 / 行业关键词 / 目标语言（出海英文 / 日文 / 西语）
  • 工作内容：
    1. 选定 1 个目标地区（北美 / 欧洲 / 东南亚 / 全球英文）
    3. 选定 1-3 个赛道方向
    4. 调研该地区的 AI 工具接受度、付费习惯、流量结构
  • 输出：01-市场大盘.md（包含地区 / 赛道初筛 + 付费力 / 流量结构）
  • 工具：
  • 网络搜索（Google / 行业报告 / Statista / G2）
  • 数据源：真实或仿真数据；不编造数字
  • 变现研究：Similarweb / G2 排行榜
  • 时间：1 天
  • 关键风险：选错地区（北美合规成本、印度懒付）—— 优先海外能做的服务（北美 + 欧洲英文为主）
  • 老板参与：拍板"这个赛道做不做"

1.2 用户画像 / 痛点调研

  • 输入：赛道方向
  • 工作内容：
    1. 采集 30-50 条真实用户反馈（Reddit / Product Hunt 评论 / G2 评论）
    2. 提炼 3-5 个核心痛点
    3. 描出 1-2 个典型用户画像（Persona）
  • 输出：02-用户画像.md（Persona × 痛点矩阵）
  • 工具：Reddit API / Product Hunt / G2 / 论坛
  • 时间：1 天
  • 关键风险：用户样本偏执 → 优先采公开真实社区里的用户反馈
  • 老板参与：审 Persona 是否符合老板直觉

1.3 竞品地图

  • 输入：赛道方向
  • 工作内容：
    1. 拉出 8-15 家竞品（同类 / 周边 / 上下游）
    2. 按"功能 / 价格 / 用户量 / 口碑"四维评估
    3. 拆解竞品的商业模型（Freemium / 订阅 / 广告 / 一次性）
    4. 挖护城河 / 弱点
  • 输出：03-竞品地图.md（包含对比表 + 差异化机会点）
  • 工具：Similarweb / G2 / Crunchbase / 竞品官网
  • 时间：1-2 天
  • 关键风险：只看出价好车的护城河、不看弱点 → 一定要问"为什么老用户会跳"
  • 老板参与：拍板差异点是否老板要背

1.4 合规 / 政策风险扫描

  • 输入：目标地区 + 业务类型
  • 工作内容：
    1. 调研 GDPR（欧洲用户）、COPPA（儿童）、COPPA、广告法（FDA/FTC）、ICP（中文）等
    2. 调研是否需 ICP 备案 / Apple 开发者账号 / 公司主体
    3. 调研税务（VAT / 销售税 / 跨境收款）
  • 输出：04-合规清单.md（合规 + 主体 + 收款策略）
  • 工具：官方文档 / 律所文章 / 实际备案路径
  • 时间：0.5-1 天
  • 关键风险：不做合规调研直接上线 → 永久收益受损、账号被封
  • 老板参与：拍板主体（个人 / 公司 / 香港 / 美国 LLC）

1.5 Phase 1 Gate（决策点）

  • 继续条件：赛道明确 + 有 3-5 个竞品 + 至少 1 个差异点 + 合规可行
  • 暂停条件：赛道过大 / 0 竞品（可能没市场） / 合规不可行
  • 输出：00-GO-结构化记录.md，包含 GO / NO-GO 判断

Phase 2：项目筛选（Project Selection，1-2 天）

2.1 决策矩阵（老板拍板）

维度 权重 评分标准
市场大小（Top 10% 市场规模） 20% 总用户量 / ARR 潜力
竞争激烈度 15% 头部 5 家各占多少
老板兴趣 / 理解度 20% "能不能讲清楚是什么"
技术可行性 20% "AI 能干多少 / 需要多少人工"
资源匹配 15% 现金流 / 时间 / 招聘可行性
长期护城河 10% "能否 6 个月防重复"
  • 输出：05-决策矩阵.md（加权打分 + TOP 3 候选）

2.2 MSP 定义（4-7 天可出）

  • 输入：TOP 1 项目
  • 工作内容：只留 1 个核心场景 + 1-2 个核心功能 + 1 个最简支付通路
  • 输出：06-MSP定义.md（一个 Goal / Non-Goal + 用户故事 × 3）

2.3 退出 / 继续决策

  • 继续条件：加权打分 ≥ 70 / 技术可行性 ≥ 80
  • 暂停条件：财务预估 ≤ 6 个月不能回本 / 技术需要外包 / 老板不熟悉
  • 老板参与：100% 拍板（这是老板的钱和时间）

Phase 3：PRD（Product Spec，2-3 天）

3.1 用户故事（User Story）

  • 格式：As a [user], I want to [action], so that [benefit]
  • 数量：8-15 条
  • 优先级：MoSCoW（Must / Should / Could / Won't）
  • 输出：07-PRD-用户故事.md

3.2 用户体验流程（User Flow）

  • 输入：核心场景 × 1
  • 工作内容：画出用户从进入 → 注册 → 付费 → 达成核心环节的全部路径
  • 工具：Mermaid / Figma / Draw.io
  • 输出：08-用户流程图.md（包含 Mermaid 代码 + 解释）

3.3 信息架构（IA）

  • 输入：用户故事 + 流程
  • 工作内容：列出所有页面 / URL / 路由
  • 输出：09-IA.md（sitemap + 路由表）

3.4 验收标准（Acceptance Criteria）

  • 格式：Given / When / Then
  • 每个流程配 1 套验收标准
  • 输出：10-验收标准.md

3.5 非功能需求（NFR）

维度 指标
性能 LCP < 2.5s / FID < 100ms / CLS < 0.1
可访问性 WCAG 2.1 AA
SEO Lighthouse SEO ≥ 95
兼容性 主流移动端 + 桌面浏览器
国际化 至少 2 语言（EN + 1 其他）

3.6 数据与隐私

  • 用户数据收集清单（必需 / 可选）
  • 隐私政策 / Cookie 政策 / 服务条款

3.7 商业化设计

  • 定价方案（老板偏好：少即是多）
  • 支付通路（Stripe / Lemon Squeezy / Creem）
  • 退款 / 退订策略

3.8 Phase 3 Gate

  • 继续条件：用户故事有 8-15 条 / 流程图清晰 / NFR 可达
  • 暂停条件：流程复杂到 7 天内不可完成 → 回到 Phase 2 简化 MSP

  • 继续条件：技术栈与老板资源匹配 / 第三方服务可接 / 部署路径明确

6.3 性能测试

  • Lighthouse（桌面 / 移动）
  • Core Web Vitals
  • 资源大小 / 加载时间

6.4 安全测试

  • HTTPS / HSTS / CSP / X-Frame-Options

6.6 A/B 测试（如适用）

  • Landing page 标题 / CTA
  • 定价方案 / 套餐顺序

6.7 Phase 6 Gate

  • 继续条件：所有测试通过 / 性能达标 / 安全通过
